## 📌 Core JavaScript Concepts


## **Q1: What is the difference between `var`, `let`, `const`?**

**var**

* Function-scoped or globally-scoped (not block-scoped).
* Can be **re-declared** in the same scope.
* Hoisted **with undefined**.
* Example:

```js
console.log(a); // undefined
var a = 10;
var a = 20; // allowed
```

**let**

* Block-scoped (only exists in `{}` scope).
* Cannot be re-declared in the same block.
* Hoisted but **not initialized** (Temporal Dead Zone).
* Example:

```js
{
  let x = 5;
  // let x = 6; // ❌ Error: Identifier 'x' has already been declared
}
```

**const**

* Block-scoped.
* Must be **initialized at declaration**.
* Cannot be reassigned (but objects/arrays can have their **contents changed**).
* Example:

```js
const y = 10;
// y = 20; // ❌ Error
const obj = { a: 1 };
obj.a = 2; // ✅ allowed
```

**Key Takeaways:**

* Use `const` by default, `let` if you need reassignment, avoid `var` in modern JS.

---

## **Q2: What is hoisting?**

* **Hoisting** is JavaScript’s behavior of moving **declarations** (not initializations) to the top of their scope.
* Applies to **var, function declarations, let/const (TDZ)**.

Example:

```js
console.log(a); // undefined
var a = 5;

console.log(b); // ❌ ReferenceError
let b = 10;

foo(); // ✅ Works
function foo() { console.log("Hi"); }
```

**Important:**

* Only **declarations are hoisted**, not assignments.
* `let` and `const` are hoisted but **cannot be accessed before declaration** (Temporal Dead Zone).

---

## **Q3: What is the scope chain?**

* The **scope chain** determines how JS looks for variables.
* When a variable is referenced, JS searches in:

  1. Local scope
  2. Parent scope
  3. Grandparent scope … up to global scope

Example:

```js
const a = 1;
function outer() {
  const b = 2;
  function inner() {
    const c = 3;
    console.log(a + b + c); // 6
  }
  inner();
}
outer();
```

* JS checks **inner → outer → global**.

---

## **Q4: What is a closure? (VERY IMPORTANT)**

* A **closure** is a function that **remembers variables from its outer scope**, even after that scope has finished executing.

Example:

```js
function makeCounter() {
  let count = 0;
  return function() {
    count++;
    return count;
  }
}

const counter = makeCounter();
console.log(counter()); // 1
console.log(counter()); // 2
```

**Why important:**

* Used in **encapsulation, private variables, callbacks, event listeners**.
* Can cause **memory leaks** if references are kept unnecessarily.

## **Q5: Difference between `==` and `===`**

| Operator | Checks                | Type coercion?             |
| -------- | --------------------- | -------------------------- |
| `==`     | Value equality        | ✅ converts types if needed |
| `===`    | Value + type equality | ❌ no type conversion       |

Example:

```js
'5' == 5  // true
'5' === 5 // false
```

**Interview Tip:** Always use `===` unless you intentionally want coercion.

## **Q6: Arrow function vs normal function**

* **Arrow function:**

  * Short syntax
  * No `this` binding → inherits `this` from surrounding scope
  * Cannot be used as **constructors**

```js
const add = (a, b) => a + b;
```

* **Normal function:**

  * Has its own `this`
  * Can be used as constructor

```js
function add(a, b) { return a + b; }
```

---

## **Q7: What is `this` in JavaScript?**

* Refers to **the object that is executing the function**.
* Rules:

  * Global function → `this` = `window` (or `undefined` in strict mode)
  * Object method → `this` = object
  * Constructor function → `this` = new instance
  * Arrow function → `this` = surrounding scope

Example:

```js
const obj = {
  x: 10,
  getX: function() { return this.x; }
};
console.log(obj.getX()); // 10
```

---

## **Q8: What are `call`, `apply`, `bind`?**

* **call:** Calls function with **explicit `this`** + arguments individually

```js
fn.call(obj, arg1, arg2);
```

* **apply:** Same as call, but arguments as **array**

```js
fn.apply(obj, [arg1, arg2]);
```

* **bind:** Returns a **new function** with `this` bound

```js
const boundFn = fn.bind(obj);
boundFn(arg1);
```

## **Q9: What is the event loop?**

* JS is **single-threaded**
* Event loop manages **execution of synchronous and asynchronous code**.
* Flow:

  1. Execute **call stack**
  2. Put async tasks in **task queue / microtask queue**
  3. Execute tasks when call stack is empty

---

## **Q10: Callback vs Promise vs Async/Await**

| Concept         | Description                                                       |
| --------------- | ----------------------------------------------------------------- |
| **Callback**    | Function passed as argument → called later                        |
| **Promise**     | Object representing **future value**, can `.then()` or `.catch()` |
| **Async/Await** | Syntactic sugar over Promise for **readable async code**          |

---

## **Q11: Microtasks vs Macrotasks**

* **Macrotasks:** setTimeout, setInterval, I/O, setImmediate
* **Microtasks:** Promise callbacks, MutationObserver
* **Microtasks run before next macrotask**

## **Q13: Difference between map, filter, reduce**

```js
const arr = [1, 2, 3, 4];
```

* `map`: transforms each element → returns **same length**

```js
arr.map(x => x * 2); // [2, 4, 6, 8]
```

* `filter`: keeps elements **based on condition**

```js
arr.filter(x => x % 2 === 0); // [2, 4]
```

* `reduce`: reduces array to **single value**

```js
arr.reduce((sum, x) => sum + x, 0); // 10
```

## **Q14: How to clone an object?**

* **Shallow copy:** only top-level properties

```js
const obj2 = { ...obj1 };
```

* **Deep copy:** nested objects are copied

```js
const obj2 = JSON.parse(JSON.stringify(obj1));
```
---


# **Shallow Copy vs Deep Copy — Example**

```js
// Original object
const original = {
  name: "Alice",
  age: 25,
  address: {
    city: "Paris",
    zip: 75000
  }
};
```

---

## **1️⃣ Shallow Copy**

```js
// Shallow copy using spread operator
const shallowCopy = { ...original };

// Modify top-level property
shallowCopy.name = "Bob";
console.log(original.name); // Alice → top-level change does NOT affect original

// Modify nested object property
shallowCopy.address.city = "London";
console.log(original.address.city); // London → nested change DOES affect original!
```

**Explanation:**

* The top-level properties (`name`, `age`) are copied independently.
* Nested objects (`address`) are **still referencing the same object in memory**.

---

## **2️⃣ Deep Copy**

```js
// Deep copy using JSON
const deepCopy = JSON.parse(JSON.stringify(original));

// Modify top-level property
deepCopy.name = "Charlie";
console.log(original.name); // Alice → top-level change does NOT affect original

// Modify nested object property
deepCopy.address.city = "Tokyo";
console.log(original.address.city); // Paris → nested change does NOT affect original
```

**Explanation:**

* Everything, including nested objects, is **completely copied**.
* Changing anything in `deepCopy` **does not touch** `original`.

---

### **✅ Summary**

| Aspect                    | Shallow Copy                  | Deep Copy                                             |
| ------------------------- | ----------------------------- | ----------------------------------------------------- |
| Top-level properties      | Independent                   | Independent                                           |
| Nested objects/arrays     | Shared (reference)            | Fully copied                                          |
| Changes to nested objects | Affects original              | Does NOT affect original                              |
| How to create             | `{ ...obj }`, `Object.assign` | `JSON.parse(JSON.stringify(obj))`, `_.cloneDeep(obj)` |

---

💡 **Interview tip:**

* If you are asked “shallow vs deep copy,” **always give a nested object example** to show you understand references vs real copies.

# **Q: What is immutability and why is it important in React?**

---

## **1️⃣ What is immutability?**

* **Immutability** means **an object or array cannot be changed after it is created**.
* Instead of **modifying the original**, you **create a new object or array** with the changes.

**Example: Immutable update**

```js id="immutable1"
// Original array
const numbers = [1, 2, 3];

// Add a number immutably
const newNumbers = [...numbers, 4];

console.log(numbers);    // [1, 2, 3]  → original stays the same
console.log(newNumbers); // [1, 2, 3, 4] → new array
```

**Example: Mutable update (not recommended)**

```js id="immutable2"
const numbers = [1, 2, 3];
numbers.push(4); 
console.log(numbers); // [1, 2, 3, 4] → original array changed!
```

---

## **2️⃣ Why is immutability important in React?**

React relies heavily on **state changes** to know when to **re-render components**.

* React **compares the previous state and the new state** to decide if it should update the UI.
* This comparison is **shallow**, so if you **mutate objects directly**, React may **not detect the change**.

**Example: Mutable state (wrong)**

```js id="immutable3"
const [user, setUser] = React.useState({ name: "Alice" });

function changeName() {
  user.name = "Bob"; // mutating directly
  setUser(user);     // React may not re-render because reference is same
}
```

* React sees the **object reference hasn’t changed**, so it **might skip re-rendering**.

**Example: Immutable state (correct)**

```js id="immutable4"
const [user, setUser] = React.useState({ name: "Alice" });

function changeName() {
  setUser({ ...user, name: "Bob" }); // create a new object
}
```

* Now, React sees **a new object reference**, triggers **re-render**, and UI updates correctly.



## **3️⃣ How to maintain immutability**

* **Arrays**

  * Use `map`, `filter`, `reduce`, or **spread operator** instead of mutating methods (`push`, `pop`, `splice`).

```js id="immutable5"
const numbers = [1, 2, 3];
const newNumbers = numbers.map(n => n * 2); // [2, 4, 6]
```

* **Objects**

  * Use **spread operator** or `Object.assign()` instead of directly modifying properties.

```js id="immutable6"
const user = { name: "Alice", age: 25 };
const newUser = { ...user, age: 26 }; // new object
```



## **4️⃣ Why React cares about immutability**

1. **Performance optimization**

   * React can use **shallow comparison (`===`)** to detect changes.
   * Immutable updates mean **faster and simpler diffing**.

2. **Predictability**

   * No side effects. State changes are **explicit**, making your app easier to debug.

3. **Time-travel debugging**

   * Tools like **Redux DevTools** rely on immutability to **replay previous states**.



## ✅ **Key Takeaways**

* **Immutability = do not change original data. Always create a new object or array for updates.**
* In React, **always update state immutably** to ensure proper re-rendering and predictable behavior.
* Use **spread operators, map/filter, Object.assign, or libraries like Immer** for complex updates.



### **Interview Tip**

If asked “Why is immutability important in React?” you can say:

> “Because React relies on **state references** to detect changes. If we mutate state directly, React might not detect it and the UI may not update. Immutable updates ensure React re-renders correctly, improve performance via shallow comparison, and make state predictable and easier to debug.”

# **Memory & Performance**

---

## **Q16: What is a memory leak?**

* Memory allocated but **not released**, causing **slow performance**.
* Example: unused closures, forgotten event listeners, large DOM references.

---

## **Q17: What is garbage collection?**

* JS automatically **frees memory** for unreachable objects.
* Helps prevent memory leaks if used properly.

---

## **Q18: How can closures cause memory issues?**

* If closures **retain references to large data** or DOM nodes → memory cannot be freed.
* Example: adding event listeners inside closure without removing → leak.

## **Q19: What is debounce vs throttle?**

* **Debounce:** delay execution until user stops triggering
* **Throttle:** limit execution to **once per interval**

```js
// Debounce example
const debounced = debounce(fn, 300);

// Throttle example
const throttled = throttle(fn, 300);
```

---

## **Q20: What is currying?**

* Transform a function that takes multiple args → **series of functions each taking 1 arg**

```js
const add = a => b => a + b;
add(2)(3); // 5
```

---

## **Q21: What is prototype & prototypal inheritance?**

* Every JS object has **prototype** → shared properties/methods
* Inheritance works by **looking up the prototype chain**

```js
function Person(name) { this.name = name; }
Person.prototype.sayHi = function() { console.log(this.name); }
```

---

## **Q22: What is Object.freeze()?**

* Makes an object **immutable** (cannot add, delete, or modify properties)

```js
const obj = { a: 1 };
Object.freeze(obj);
obj.a = 2; // ❌ ignored
```
