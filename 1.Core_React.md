### 📌 React Fundamentals

**Q: What is React and why is it used?**

* React is a **JavaScript library for building UI**.
* It allows **component-based development**, making UIs **reusable and maintainable**.
* React is used because of **fast rendering (Virtual DOM), modular code, and strong community support**.

---

**Q: What is the Virtual DOM and how does it work?**

* Virtual DOM is a **lightweight copy of the real DOM** in memory.
* React updates the **Virtual DOM first**, compares it to the previous version (**diffing**), and **only updates the real DOM where changes occurred**.
* This improves **performance**.

---

**Q: Difference between state and props**

| State                           | Props                                |
| ------------------------------- | ------------------------------------ |
| Managed **inside** component    | Passed **from parent**               |
| Can change over time            | **Read-only**                        |
| Triggers re-render when updated | Does not trigger re-render by itself |

---

**Q: What causes a component to re-render?**

* Change in **state**
* Change in **props**
* Parent component re-rendering
* Context value change

---

**Q: What is JSX?**

* JSX = **JavaScript + XML-like syntax** for defining React UI.
* Example:

```jsx
const element = <h1>Hello, React!</h1>;
```

* JSX is **compiled to `React.createElement()`** by Babel.

## 📌 Component Design

**Q: Functional vs Class components (which is better and why?)**

* **Functional components**: simpler, use **hooks**, easier to test, no `this` binding. ✅
* **Class components**: older, require `this`, more verbose.
* **Best practice now**: Functional components for most cases.

---

**Q: What are controlled vs uncontrolled components?**

* **Controlled**: React **controls form input** via state.

```jsx
<input value={value} onChange={e => setValue(e.target.value)} />
```

* **Uncontrolled**: DOM controls input, access via `ref`.

```jsx
<input ref={inputRef} />
```

* Controlled is **preferred** for React apps.

---

**Q: How do you lift state up?**

* Move the **shared state** to the **closest common parent**.
* Pass **state and setter** as props to children.

---

**Q: What is prop drilling and how do you avoid it?**

* **Prop drilling** = passing props **through many layers** just to reach a child.
* Avoid with:

  * **Context API**
  * **Redux**
  * **Custom hooks**

---

## 📌 React Lifecycle (Hooks version)

**Q: How does `useEffect` replace lifecycle methods?**

| Lifecycle              | Equivalent in Hooks                                             |
| ---------------------- | --------------------------------------------------------------- |
| `componentDidMount`    | `useEffect(() => {}, [])`                                       |
| `componentDidUpdate`   | `useEffect(() => {}, [deps])`                                   |
| `componentWillUnmount` | return cleanup function: `useEffect(() => () => cleanup(), [])` |

---

**Q: Difference between `useEffect` and `useLayoutEffect`**

* `useEffect`: runs **after painting** (non-blocking).
* `useLayoutEffect`: runs **before painting**, can block render (used for measuring DOM).

---

**Q: What happens if you don’t clean up effects?**

* Can cause **memory leaks**
* Can trigger **unwanted side effects** (e.g., multiple event listeners, intervals)

---

## 📌 Performance Optimization

**Q: What is `React.memo`?**

* HOC that **memoizes a component**, re-renders only if **props change**.
* Useful for **pure functional components**.

---

**Q: Difference between `useMemo` and `useCallback`**

* `useMemo(fn, deps)` → **memoizes a value**
* `useCallback(fn, deps)` → **memoizes a function**

---

**Q: When should you optimize?**

* Only **when performance is an issue**
* Over-optimizing can **add complexity**

---

**Q: What causes unnecessary re-renders?**

* Changing state too often
* Passing **new object/array/function references** each render
* Parent re-rendering without memoization

### Q: What is event delegation in React?

**Event delegation** is a technique where instead of attaching an event listener to **every single DOM element**, you attach **one listener at a common parent**, and handle events **for its children** from there.

React implements this internally using **synthetic events**.

---

### 1️⃣ Synthetic Events

* React doesn’t attach events directly to every DOM element.
* Instead, React creates a **SyntheticEvent** (a wrapper around native browser events).
* This ensures **cross-browser compatibility** and **consistent behavior**.

---

### 2️⃣ How delegation works in React

* React attaches **one event listener to the root container** (like `document` or the React root).
* When a child element triggers an event (like `onClick`), React:

  1. Captures the event at the root (bubbling phase)
  2. Checks the event target
  3. Calls the **appropriate event handler** defined on the child

✅ Example:

```jsx id="8r0nvb"
function App() {
  const handleClick = (e) => {
    alert(`You clicked: ${e.target.textContent}`);
  };

  return (
    <div onClick={handleClick}>
      <button>Button 1</button>
      <button>Button 2</button>
    </div>
  );
}
```

**What happens here:**

* Only **one `onClick` listener** is attached to `<div>`.
* Clicking **Button 1** or **Button 2** triggers the same `handleClick`, and `e.target` tells React which element was clicked.
* This **reduces memory usage** and improves performance when you have many elements.

---

### 3️⃣ Benefits

* **Performance:** You don’t need multiple event listeners.
* **Consistency:** React handles cross-browser issues automatically.
* **Simpler cleanup:** Only need to remove one listener at root.

---

### 4️⃣ Common Confusion

* Some think React attaches a listener to **each button individually** → ❌ Not true.
* React **delegates all events** from the root container using synthetic events.



---

**Q: Difference between `onChange` and `onInput`**

* `onChange`: fires **when input loses focus** (classic HTML) in JS, in React it fires on **every value change**
* `onInput`: fires **on every input change**, browser native
